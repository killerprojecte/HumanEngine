# Default source logger and application shutdown

`Open` now creates and owns `observability.StoreLogger` when `Options.Logs` is absent. Construction remains lazy; the first serializable record acquires independent bounded stdout and canonical-file leases. An optional shared `LogRegistry` supports embedding/tests, not an alternate logging mode. Production uses the process registry. Producers depend on `Emitter`; HTTP reads depend on the pure `RetainedLogger` view. The writable launcher gets the actual logger from `Application.Logger`, emits flat source records with their readable stdout prefix, and does not construct a parallel raw logger.

The historical raw `observability.New` utility and its Close/Status/error behavior remain intact. Its additive `WaitPhysicalClose` only observes the existing done boundary and never initiates a close. The LogOwner dependency now explicitly requires that physical observation rather than using error types as evidence of liveness.

Producer and accepted-request shutdown order is unchanged. After all producers physically drain, the application emits app.drained once, starts one continuing logical close plus explicit physical join, and only then releases the installation/database. A caller's canceled context detaches that caller without canceling accepted cleanup. Retries wait the same operation and do not emit another final row or switch a generation. Logging health failure is returned, but does not skip database cleanup after physical ownership is complete. A failed startup returns no finalized partial owner, even if logging health failed during completed cleanup; an actually unfinished physical drain retains its partial owner and installation.

An explicitly supplied Logs remains borrowed: Shutdown drains the application and releases its installation without closing that foreign logging lifetime. ShutdownAndFlush explicitly closes/joins it. Calling borrowed Shutdown first has already released that installation, so a later ShutdownAndFlush cannot retroactively retain it. The default source-owned path always joins logging first. Nonlast Store leases flush their own target but do not wait for another Store's lifetime.

GET logs and general status retention remain pure reads. `/api/logs/status` remains503. HTTP101, default CLI refusal, Docker, and the read-only preview entry point are unchanged. This is not whole-engine migration acceptance.

## Validation

This application batch completed three separately scoped stages against the same source bytes:

- Stage1 (session3596, exit0): all nine affected packages compiled in both default and native profiles with zero tests executed by the compile-only commands. Both complete default logging package race suites then passed48 top-level tests and exact26+7 Store source cases, with no skips. Compilation of the native external test bridge is distinct from its later physical behavior proof.
- Stage2 (session66194, exit0): selected native app13, regular-file bridge1 and HTTP7 top-level tests, plus26 named leaves, passed all47 exact run/pass pairs under race checking. This covers default owned and explicit borrowed logging, startup/health cleanup, canceled/repeated shutdown, nonlast Store leases, held producer/HTTP drain, real file write/fsync/held close, same-process descriptor/owner Done before installation reopen, and retained-log18/general-status6 source HTTP cases. It is not the complete app or HTTP package suite.
- Stage3 (session32788, exit0): the complete launcher profiles passed default4 and native8 top-level tests plus2 native leaves, along with the actual installed V1 producer/configuration/ingress/shutdown/restart regression. The native command tests cover TCP/authentication, held accepted requests, signals, drain/restart and competing-writer rejection using the actual source logger. Both profiles of nine-package vet and formatting checks for all26 changed Go files passed.

Every stage checked source/native-asset hashes before and after execution. Strict gates reject missing, extra, duplicate, skipped or failed required tests. Existing source fixtures and guest artifacts were preserved; this app validation did not regenerate source oracles or build guest WASM. The logger starts no Node process; real V1 processes in the application fixtures belong to the existing app lifecycle.

Earlier failures remain part of the evidence. Session67397 failed to compile a test that called Close through the intentionally narrow RetainedLogger view; only that fixture was corrected to keep its locally created raw owner for cleanup. Session90932 passed app13+2 but later native links ran out of space. Session17983 failed its first native link before tests because /tmp was a separate nearly full tmpfs despite sufficient workspace space. The runner was corrected to use a dedicated workspace temporary directory, verify the actual temporary/cache/evidence filesystems and capacity, and run packages sequentially. The complete47-case stage was rerun successfully without changing production or expected test bytes.

Test-only file hooks live exclusively in `_test.go`. The native external test starts the real app and proves fd closure, native owner Done and installation reopen in one process, without a production injection API or treating process exit as a physical join witness. These results do not claim whole-engine migration acceptance.
