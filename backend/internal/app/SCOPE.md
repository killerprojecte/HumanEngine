# Native application composition checkpoint

This package composes actual native owners for integration and explicit future
runtime-preview use. The command entry point is unchanged: `--read-only-preview`
remains read-only, and the default command does not start this application.
This is not a claim of complete TypeScript Engine compatibility.

## Composed and exercised

- Installation, separate recovery authority, main SQLite database, credentials,
  pinned ICU/collation, native image codec and physical model budget service.
- HTTP settings/models, scenes, plugins, Meme, habits, Experience administration,
  diagnostics and model-call queries through their concrete stores and gates.
- Shared V1 bridge/manager host, actual adapter ingress, native model protocol,
  model-facing tool execution, delivery, disable, shutdown and restart without
  replay. No substitute JavaScript Engine or fake adapter transport is used.
- Model configuration is captured once per foreground Router/turn. An HTTP model
  update affects the next turn while accepted stages and continuations retain
  their Router. Cross-Router continuation ownership remains enforced.
- Actual semantic memory, ordinary learning, projections, working sets,
  commitments, relations and knowledge dependencies. Commitment/relation base
  schemas are initialized through their real constructors' Initialize methods.
- Model-facing `memory.search`, `memory.person` and `memory.identities`, including
  actual permission checks, original receipt identity, deferred planner selection,
  memory delivery tracking, identity state validation and scoped cached guards.
  Model-read capture is registered once by Meme; memory and identity compose
  with existing hooks rather than replacing them.
- Four additional model-facing tools: `memory.commitments`,
  `memory.commitmentTimeline`, `memory.commitmentHistory` and `memory.history`.
  Exact source descriptions, schemas, settings filters and advertisement order are
  retained. Guard capture remains current/history/timeline/historical before
  identity. Historical reads use Begin; commitment reads use GateTool.
- A genuine installed-application test proposes separate ordinary memory and
  commitment declarations, delivers original receipts through V1 model queries,
  and selects all four state tools across two plans within the source four-state
  limit. A third native send is held before transmission, answer permission is
  revoked through HTTP, and release produces no additional transmission.
  Clone/foreign/scope rejection, recall invalidation, restart/no replay and physical
  shutdown are checked. These are synthetic protocol/platform inputs, not proof of
  a live third-party platform connection.
- Dynamic tool getters run at source operation boundaries. Runtime tests cover
  changing settings and tool availability, concurrent turns, execution-time send
  effects, first matching delivery ownership, current learning flags and current
  image extensions. Completion diagnostics do not add a sending authorization gate.
- Experience lifecycle and planner context gate/capture, actual HTTP administration,
  retained source recall, same-writer invalidation and physical callback drain.
- The source default `learningEnabled=false` scene update is a normal successful
  HTTP path. Experience pause precedes runtime scene registration; semantic
  configuration precedes ordinary-learning, semantic, contextual and media-task
  cancellation. The application owns these effects once, avoiding duplicate epochs.
- Contextual proposal owner and keyed media-task lifetime are real owned services,
  with edit/recall/scene cancellation and physical shutdown joins. No media-ingest
  producer is currently installed in this graph, so this is not media processing.
- Async structured logs retain request/scene/turn/stage identifiers and controlled
  failure codes. Raw internal errors are not serialized into plugin events or logs.
- Startup failure cleanup, uncancelled held HTTP shutdown, accepted runtime/provider
  cleanup and database-last close are tested. A failed drain does not close borrowed
  dependencies or claim success; the application remains available for retry.

## Remaining application boundaries

- No runtime command launcher is exposed yet. A future explicit runtime-preview
  option must define installation/configuration inputs without changing read-only
  preview semantics or silently selecting this graph as the default backend.
- Remaining source model tools, complete prompt/manual-rule composition and all
  exposure domains are not all wired. Workspace, knowledge and semantic
  exposure guards are not implied by the composed memory, identity, commitment
  and historical guards. Contextual `learning.propose` is now a model
  tool in this bounded graph, without those remaining exposure domains. Complete
  Experience model-facing tools are also outstanding.
- Source-wide recall preparation ordering (including every memory/habit domain),
  proactive scene timer binding and complete global Engine startup hooks remain.
- Four real built-in WASM artifacts are built and required by the native test
  profile, but this graph's V1 integration does not prove all four built-ins have
  their complete product capabilities installed. Native OneBot and full SnowLuma
  transport/history/media integration remain separate work.
- Native media ingestion, historical image transport, private media cache/fetch and
  the unresolved HTTP 101 behavior are excluded. No legacy readImage bridge or
  permissive media owner is substituted.
- The existing async Logger is used; complete source log retention/status/delivery
  route equivalence is not claimed. Independent read publication still preserves
  recovery checks; no constant-time cross-connection audit performance claim is made.
- Lazy security schema initialization covers SaveModels and its write-only secret
  mutations. It is not generalized to every standalone credentials/settings writer.

## Evidence and limits

The frozen memory graph r5 passed actual four-WASM build, all ten native app tests
without skips, race instrumentation, three-package vet and unchanged input checks
(session 32053). This includes real memory/identity selection through model send,
HTTP model replacement, recall, disable/restart, Unicode provider payload, startup
failure and held-HTTP drain. Default logical tests and runtime diagnostic tests
passed in r4 (session 27784); five native-only app tests explicitly skipped in that
profile and are not counted as default behavioral passes. The earlier native r4
identity nested-publication timeout is retained as failure evidence; its standalone
three-file repair passed source/Identity race/vet (51529) and was published separately.

These results belong to those exact frozen inputs. A new assembly on the latest
public plugin-directory layout requires its own merged compile/native graph check.
Package test durations are not HTTP latency or migration performance benchmarks.

## Contextual learning tool composition (bounded application graph)

The application advertises the source learning.propose definition with its eight
graph/commitment/knowledge flag combinations and delegates execution to the existing
contextual proposal owner. Actual memory exposures and model-read/current-commitment
guards use the current queue writer, without retaining a write session. Historical,
identity and current freeform-learning rejection paths preserve source semantics.
Learning-only scene revocation cancels queued learning while participation-enabled
replies remain allowed; participation revocation is a separate runtime policy.

Native focused evidence covers real model selection, queued foreground admission,
ordinary proposal persistence, history/identity/current refusal, and queued learning
revocation with physical idle and zero revoked rows. This is not full learning parity:
semantic/workspace/knowledge exposure domains are not composed or advertised.
Pending recall, changed-scope, typed commitment learning and concurrent-writer races
are not established by this fixture. No synthetic native replacement of guest logic
is introduced. A writable launcher, installation packaging/configuration and OS-signal
stop lifecycle remain separate work; --read-only-preview and HTTP 101 are unchanged.

## Relation receipt and contextual entity composition

The relation model tool now uses the existing qualified relations read owner. Its
original whole linked-memory group must be delivered before exact backing refs and
a detached relation guard reach contextual learning. Validation borrows the current
read or writer authority and checks current graph flags, relation snapshots, complete
counterclaim groups and temporal applicability. It does not reopen a root publication
or retain a writer. Advertisement follows historical memory; guard capture precedes
commitment state, matching source order.

The relation fixture exercises real proposal admission, model selection, contextual
existing-entity reuse and SQL persistence; this does not establish semantic, workspace
or knowledge exposure parity. Native platform coverage and the separate writable
launcher remain outside this batch.

## SnowLuma builtin installation candidate

The explicit native application graph now registers SnowLuma alongside typing-delay.
Registration does not enable a fresh builtin: credentials/configuration and the
existing Manager enablement state remain authoritative. Snow configuration,
startup credential selection, profile/history/receive decisions, media selection
and four-field original validation, send ordering and receipts execute in its
bound WASM guest. Native installation supplies transport, credentials, original
file IO and existing Engine authority owners. Disable/reconfigure logically
revoke the exact generation and physically drain its IO before WASM retirement.

The r9 app integration (session 24752) exercised real Runtime text/media dispatch,
committed receipts, original admission/removal, hot configuration, policy/runtime
unload and physical close. The same app test and linked-artifact hash/manifest test
also passed in a bwrap mount-isolated directory without application source or an
external WASM file. This proves the specified Snow installation path with explicit
Node/ICU/libvips/sqlite-vec runtime dependencies; it is not full CLI/container or
HTTP installation acceptance. The exact fresh-public composition passed its focused race/native application,
linked artifact, reproducible recipe, vet and frozen-input checks. Adapter status API wiring remains a separate batch.

Cold compilation is a known unresolved performance cost: configuration took
about 83–85s, enable 53–55s and hot configuration 56–58s. Disable completed in
milliseconds, with no policy/runtime guest retained. API closure does not claim
immediate RSS reclamation. Disk compilation-cache optimization requires a separate
owner/lifetime review and actual cold/warm measurements. Increasing the test's
setup budget does not resolve this production cost. The command entry point is
unchanged and does not activate a default server.
