# Live experience owner candidate

This package implements the live `ExperienceService` policy/trial owner in native Go. It is a review candidate, **not** a claim that the robot migration or runtime integration is complete.

## Implemented responsibilities

- Exact feedback roots, duplicate conflicts, explicit withdrawal/counterexample checks, source/snapshot qualification, candidate proposals and mechanical validation.
- Policy CAS/review, active/expired support handling, hints, snapshot validation, observed-use storage, source revocation and deletion.
- Persistent trial start/collect/promote/suspend/expire/erase, independence gates and immutable evidence bindings. Authority intent precedes each dependent mutation; default trial writes raise minimum reader 9. `BeforeTrialWrite` is an explicitly trusted source-equivalent override, not the production default.
- `NativePorts` reads real persisted settings/scenes/recall state and source identity/edit proof through the supplied `WriteSession`. The required live-preview callback must be composed with the actual runtime cache, never a model/tool/history result. There is no permissive preview fallback.
- `RuntimeRecallPreparation` joins existing ingress recall ownership. Offline replay remains the existing `recoverydomains` owner and does not become a live fallback.
- Domain/feedback helpers, fixed action rendering, native observed-operation eligibility and all 16 fixed mechanical holdouts are included.

All dependent proof/config reads and SQL writes use one root owned writer. Nested service calls use savepoints; callbacks cannot retain the session after return. Ordinary caught SQL errors stay recoverable; native transaction loss poisons the root. The internal `fault` unwind converts only package-owned synchronous failures to errors before transaction completion and does not swallow arbitrary panics.

Source product bounds (20 outcomes, 40 policy page, first 200/201 stored policies, 3 hints, 20 target uses, two positive reports and 4096 trial tombstones) are retained. No additional admission/resource caps were added.

Existing `botruntime.Runtime.Snapshot` performs display authority projection and must not be called from an owned writer in a way that re-enters authority. 3. Port `src/memory/experience/runtime-hints.ts`: `LearningPaused`, `Received`, `PlannerContext`, `Outcomes`, `DeliverOutcomes`, `Propose`, `DeliveredTool`, `Sent`. This must retain per-turn learning epochs, source-exposure identity/deep-equality receipts, semantic-read ordering, observed applied operations, deferred exposure and ACK-only target association. ACK must not infer conclusion-first ordering.
4. Compose those methods into `botruntime.Extension` (`Received`, planner contribution, tool `Delivered`), `TurnContext.AddDependency` / scoped validation / deferred memory exposure, and transport sent events. Scope validators must use the active read/write authority rather than opening another transaction during send validation.
5. Wire native experience admin HTTP handlers, startup/shutdown owner composition, learning-pause epochs, and composite recall preparations without replacing other domain callbacks. No endpoint or engine composition was changed in this patch.
6. The final owner candidate passed native-ICU race tests and vet with REQUIRE_ICU=1, including the actual source-reference matrix and close/reopen tests. Complete integrated CI and caller-graph acceptance remain separate. Full runtime composition and source-free robot acceptance remain unclaimed.

`RecoverState` / `RecoverDelete` are deliberately not exposed by the live service: existing `recoverydomains.Owner` / `Trials` exclusively perform maintenance-gated replay and qualification. New service code never synthesizes evidence on restart.

## Complete raw-reference presence correction (v5)

Raw reference material now has an explicit presence wrapper with an arbitrary lossless JSON value, separate from the optional typed `sourceevents.Ref`. Missing is distinct from explicit null, false, zero, empty string and every other JSON value. DTO decoding preserves all such material and only populates typed authority when strict parsing succeeds; no invalid presence marker or numeric coercion is used. Historical serialization and qualification retain the raw value exactly. An unregistered snapshot accepts only absent material; a registered snapshot applies the source's truthiness check and then parses the complete raw value before using the typed authority.

`presence-oracle.json` is generated by actual Node v24.22.1 ExperienceService, not only a schema parser. Its 112 cases cover source and target, registered and unregistered, snapshot and non-snapshot, each across missing/null/false/true/zero/number/empty string/string/empty array/array/empty object/valid object/fractional object/extra-property object. Native tests compare admission, exact source error branch where applicable, presence and retained values, stored count, serialized outcomes, qualification hashes and persisted decode round-trips. Feedback adapter truthiness also uses the raw value rather than treating nil typed authority as absence.

The v4 native test results do not validate this v5 delta. v5 has source-oracle and static-format evidence only until the separately granted native test run completes. No runtime/read-scope bridge changes are included here.
