# Source Store logging, reusable native core

`NewStoreLogger` is the source-compatible owner intended for the writable application's default composition. It is independent of the historical raw `New`/`Logger` utility: that API, its error behavior and all its prior tests remain unchanged. This core checkpoint does not yet bind the application or `/api/logs/status`. That route remains 503; GET logs, CLI/default flags, Docker and HTTP 101 are unchanged. Default application binding is the next required batch, not a permanent opt-in.

## Source and native responsibilities

The constructor resolves the database/log-directory rules but creates no channel. `Emit` snapshots caller data and serializes the flat source row once; retention precedes closed checks and sink admission. Source stdout is the readable prefix plus the same flat JSON bytes, not a separate stderr stream. Original event level controls reserved priority even if fields override the row's level. Lazy acquisition is stdout then file, before enqueue stdout then file. These two bounded physical owners are independent. Retained-only degradation notices are limited to one per 60 seconds, have no sink newline in their byte accounting and never recursively enter sinks.

`Retention` and `RetainedJSON` are pure snapshots. `LoggingStatus` exposes the source nullable per-lease status and can generate the source retained-only notice. Neither read acquires or replaces a lease. All serialization, acquisition, channel calls and waits occur outside the Store mutex; no third record queue or per-record goroutine exists. Go map fields have stable sorted-key order; nested `jsjson.Object` preserves explicit source insertion order and WTF-8 semantics. Custom Go JSON marshalers are called once per captured occurrence. Nonfinite JS numbers serialize as null; cyclic/unsupported values are counted as unserializable without sink admission.

`CloseLogs` seals admissions, begins file then stdout and settles both even if either fails. Every caller has an independently continuing close round, including after context detachment. `CloseLogsSync` shares its deadline across admitted-setup wait, file and stdout. In single-threaded source, synchronous acquire cannot overlap close; in Go it can. If this additional native wait exhausts the budget, sync close returns incomplete and leaves an independent close round responsible for finishing the already admitted work and releasing its leases.

Logical health is not physical ownership. `WaitPhysicalClose` is an explicit join observation independent of a canceled or degraded Close result. It cannot create a new generation. `Lease.WaitPhysicalRelease` waits on retired generation Done only if this lease was the last release on its first release. A nonlast holder does not wait another Store's lifetime; later acquisitions never change this captured responsibility. `BeginClose` extracts synchronous release/barrier admission without changing the single-active-control/follower resampling rules or original deadline.

The owning application must drain producers first, finish logging and join these physical tails before releasing its installation writer lock. A health failure must not skip database cleanup once physical ownership is complete. Conversely, a canceled close must not be treated as proof that cleanup finished. The logger core itself does not own database, authority or diagnostic cleanup callbacks.
