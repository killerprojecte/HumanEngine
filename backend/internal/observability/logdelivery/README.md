# Native source-compatible log delivery owners

This package implements the per-sink `src/diagnostics/log-writer.ts` contract. It is a dependency checkpoint, not the application's logger or a completed `/api/logs/status` migration. The old `observability.Logger`, Store retention/formatting/notices, app composition, route bindings, CLI defaults, Docker entrypoint, and HTTP 101 behavior are unchanged. The eventual application default must use the source owner; this package does not introduce a permanent opt-in escape from parity.

## Ownership and API

- `Acquire(directory)` uses the process-wide registry. Empty directory is borrowed stdout. `NewRegistry(stdout)` provides a deliberately isolated registry for embedding/tests. Share a registry when Stores may use the same directory; separate registries are not mutually coordinated.
- `Registry.Acquire` resolves existing ancestors and symlink aliases without creating directories. Acquisition starts one native goroutine per channel, matching the source worker acquisition boundary. Registry construction and status reads start none. The later Store layer must defer acquisition until its first serializable log.
- `Lease.Enqueue(record, priority)` reserves exact UTF-8 bytes and one whole record before copying. Input uses canonical WTF-8, the representation used by `jsjson`; lone surrogates become U+FFFD. `warn`/`error` classification and JSON/readable formatting belong to Store, not this package.
- `NewChannel(options, stdout)` is an explicitly standalone channel. Optional limits are pointers so omitted and invalid explicit zero remain distinguishable. Queue limits/defaults and priority reserves are the source values; zero rotation threshold is legal.
- `Status` is an owned snapshot with a nullable sanitized `LastFailure`. Reads never replace a closed generation. Rejections are sticky health loss; the latest enqueue rejection may replace an earlier failure token. Native path/error strings never enter it.
- `Flush(ctx, timeout, close)` captures a generation-local accepted target. Its complete prefix may coexist with later pending records. Only one control barrier is admitted at once. Followers wait for its finalized acknowledgement, then sample the current accepted prefix before posting a new control. Per-flush wait continuations retain their own absolute deadlines after caller cancellation; there is no per-record goroutine. Earlier rejection makes completion/durability false even after accepted records drain. Only file output can be durable.
- `Lease.Close` releases once, flushes a nonlast holder, and closes the last holder. Repeated asynchronous close observes its retired generation; repeated `CloseSync` returns nil. Released enqueue is a lease-local rejection. Other holders' same-generation delivery remains visible, but a replacement generation does not appear in a retired handle.

## Cancellation and physical completion

Caller context cancellation detaches the wait, not the close operation. The initiated barrier and its absolute source timeout remain active. A retry joins the same tail. Source timeout sets `flush_timeout`, stops admission, hides pending credits, and derives `unconfirmed = accepted - written - failed`; it does not assert that a blocked native operation ended. A late write can still settle written/failed and shrink unconfirmed.

`Closed` is a confirmed descriptor-close/cleanup boundary, not the public status string `closed`. Successful close may permit a replacement after fd closure before the native loop's final bookkeeping returns. After abandonment, a channel becomes replaceable only after its physical operation and descriptor cleanup return. `Done` follows that cleanup and the identity-checked registry exit bookkeeping. No logging record, fsync, close, or registry callback remains after Done. A goroutine is not a Node Worker process; there is no Node launch in this package. The native subprocess test is supplementary shutdown evidence, not a substitute for same-process owner tests.

A blocked writer is never closed by a cancelling caller. The owning worker performs cleanup after the physical operation returns. Borrowed stdout is never globally closed or fsynced. Actual `*os.File` stdout and file output use `SyscallConn.Control` and one native write syscall per attempt, preserving partial/EAGAIN visibility. They never call `File.Fd()` or a hidden retry loop. Generic injected `io.Writer` adapters may hide syscall behavior and are not a raw-descriptor parity claim. File and stdout have independent workers; a held stdout cannot hold file progress. Locks protect admission/counters/identity and are not held across physical I/O, retry waits, drain waits, or writer/trace/exit callbacks.

## File behavior

Files are lazily opened `a+` with requested mode 0600 under directories requested as 0700. Existing modes are not changed. Interrupted non-newline tails rotate rather than merge with a new row. Rotation occurs before the next record only when existing size is strictly greater than the threshold (default 2 MiB), with fsync/close before rename and backups `.1` and `.2`. Partial writes advance only the remaining suffix. A nonzero write plus any error is terminal, including EAGAIN; only zero-byte stdout EAGAIN/EWOULDBLOCK retries with 2/4/8/16/32 ms backoff. Fsync/close failure degrades health without fabricating a failed record.

## Evidence and tests

`../log-channel-memory-source.json` is the actual-TS oracle expanded to 25 cases, SHA256 `41017ff90f0ee7475e54d40a760853202ee48f75b81ace6757652d04f6a31e80`, source SHA256 `e39bdbc29f063267991b38ec8a36e903dbd12388e2d1cb803915ede65dac8060`. Its generator executes the real LogChannel, immutable workerSource, registry, and leases with controlled Worker/fs boundaries. It is not OS-durability evidence. The differential Makefile runs its `--check` mode.

The original 24 cases are unchanged. The added actual-source three-admission case was generated and checked in terminal-0 Node session 76904. All 25 cases have native consumers:

- Cases 0–16 and 23: `TestSourceChannelOracle` compares every status/result field, admission arrays, UTF-8 byte content, and retry backoffs at controlled boundaries. Native terminal-write tests additionally assert prefix/no replay and syscall counts.
- Cases 17–21: `TestSourceRegistryOracle` compares all source results, history/status fields, released handles, identity, worker count, and canonical parent alias sharing.
- Case 24: `TestSourceConcurrentFlushResamplesAfterWait` reproduces three admissions around two flush calls and compares the complete results and real-file operation sequence. The second call retains target 2 but flushes through 3.
- Every source `operations` field is compared: the ambiguous partial writer in `TestSourceChannelOracle`, four additional actual-file/registry traces in `TestSourcePhysicalOperationTraces`, the rotation trace, and the added three-admission trace.
- Case 22: `TestSourceRotationOnRealFilesystem` compares the exact source status, final files, and full significant operation sequence against real files, fsync/close, and rename.
- Additional native tests cover real file permissions/lazy open/reopen; actual descriptor partial writes and fsync/close wrappers; actual nonblocking stdout fd partial progress, EAGAIN/backpressure, stop without draining the suffix, unchanged fd flags, and borrowed fd reuse; a separately labelled injected blocking writer/pipe tail; same-process held actual file write through timeout, canonical reacquire, late settlement, fd closure, and safe replacement; held fsync/close; concurrent 64-holder registry access; caller cancellation; backoff cap/reset; and native process shutdown after owner completion.

The harness tests `worker_failed`, `worker_exited`, transfer failure, and encoding failure via private seams because Go does not have a Node Worker transfer boundary. Such cases verify state/ownership behavior, not a claim that a native Go queue performs structuredClone or that injected errors prove an actual OS failure. Physical successful fsync calls and post-close descriptor checks do not simulate power loss or establish stronger filesystem guarantees than the OS provides.
