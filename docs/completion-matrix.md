## Deployment-side checks still needed

No deployment was authorized or performed. Configure credentials locally through environment-variable references, never in chat or repository files. For joint verification, useful **non-secret** details are host OS/architecture, Node version, SnowLuma version/build and enabled OneBot mode, intended bot account/scenes, provider protocol/API model names and declared text/tool/vision/embedding support. Supply credentials only on the host.

Then test one disabled-by-default scene: enable participation/learning deliberately, verify a passive private reply, a permitted group reply, received recall and history backfill, one animated image roundtrip, and restart without replay. Check actual latency/cost and conversational behavior with representative consented traffic. A missing/offline recall notification cannot be inferred with certainty.

The upstream dependency advisory and observed production exposure limits remain in `SECURITY.md`; the audit is not clean. Browser appearance/interactions, real provider/QQ behavior, recipient animation and target-machine capacity remain unverified until these checks are actually performed.
