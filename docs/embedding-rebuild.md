# Configurable embedding dimensions and generation rebuilds

## Contract

`Model.embeddingDimensions?: integer` is omitted by default: the request keeps provider-native output. Explicit values are sent as OpenAI-compatible `dimensions`, or passed to custom adapters in `context.model.embeddingDimensions`. The application storage guard is 1–16384; this is **not a provider capability claim**. Batch size remains independently configurable, default 4. Returned vectors must be finite, nonzero after float32 conversion, consistent, and match a configured width. No implicit padding/truncation occurs.

Primary-source verification (2026-10-26):

- OpenAI documents `dimensions` for text-embedding-3 and later, not all models: https://developers.openai.com/api/reference/resources/embeddings/methods/create
- Qwen's model card describes Qwen3-Embedding-8B dimensions 32–4096: https://huggingface.co/Qwen/Qwen3-Embedding-8B
- Gitee's current hosted-model page and API docs are client rendered and did not expose a reliable dimension contract to the documentation reader: https://ai.gitee.com/polaris_/Qwen3-Embedding-8B and https://ai.gitee.com/docs/openapi/v1 . Upstream capability alone did not prove hosted support. Subsequently, an explicitly approved host-only probe on 2026-10-26 made exactly two requests to https://ai.gitee.com/v1/embeddings for Qwen3-Embedding-8B: requested 1024 and 4096 both returned HTTP 200, one row at index 0, exact requested width and finite nonzero values (14 reported tokens each, no retries). This establishes those two widths for that hosted model at that time, not every dimension/model/provider or end-to-end rebuild behavior. An ignored setting still produces `embedding_dimensions_mismatch`; the application never manufactures vectors by silent resizing.

## Lifecycle and migration

`engine.embeddingIndex.status()` returns configuration state `unconfigured`, `needs_rebuild`, or `ready`, optional active generation metadata, current `coverage` counts (`eligible`, `indexed`, `pending`), and the most recent rebuild job. `ready` means the active encoder matches, not that every current memory has a vector; always display pending coverage. Coverage counts only vectors compatible with the currently selected encoder; a stale/incompatible generation reports indexed=0 and pending=eligible, while retained vector counts still expose stored old data. Job states: `running`, `paused`, `failed`, `cancelled`, `completed`. Metadata includes progress, actual dimensions, a fixed sanitized error code, and `requiresRetryConfirmation`.

- `start(expectedJobId?, expectedEncoderRevision?)` is an explicit cost-bearing admin operation, not triggered by saving model configuration.
- `pause(expectedJobId?)`/`cancel(expectedJobId?)` stop the current job without changing the active pointer. Cancellation cannot publish.
- `resume(confirmUnknownRequest = false, expectedJobId?)` resumes completed checkpoints; a potentially billed in-flight batch requires explicit confirmation. Unknown transport/cancel/restart outcomes are never silently retried.
- A transactional owner lease (30 seconds, renewed every 10 seconds only while the job runs) prevents competing workers from starting duplicate work. Startup/status never interrupts a live owner. After crash/lease expiry the job becomes paused; explicit resume is required and an uncertain prior request requires confirmation. No chat replay, background auto-resume, or historical extraction occurs.
- `settled()` and `dispose()` allow bounded lifecycle management/testing.

A fresh database that was empty at engine construction automatically activates its first validated learning vector, preserving normal learning behavior. Existing unknown legacy spaces/memories are retained but not silently trusted/adopted or re-embedded: lexical fallback and an explicit rebuild are required. Model/dimension/deployment changes never reuse old vectors with a new encoder. Credentials, credential names, timeouts, pricing and batch size do not form semantic identity. Credentials are never persisted with index jobs; secret-bearing endpoint URLs are rejected.

Each rebuild has a distinct generation even for identical encoder settings. Existing BLOB vector storage already supports independent spaces; no destructive fixed-width migration is needed. A staging space is populated in bounded batches, with current eligibility and content hashes rechecked transactionally before write. A successful final pass checks coverage and active-pointer compare-and-swap before atomic cutover. Retention is bounded to the active generation, one prior successfully published generation, and the current resumable staging generation. Starting a replacement job or publishing a successful generation prunes older derived generations/checkpoints; legacy spaces and original memories are never automatically deleted. Status reports retained generation/vector counts. Existing active vectors remain untouched until success; deletes/recalls/invalidation continue to remove vectors across generations. Newly added/edited eligible memories are included in subsequent batches. Proof quarantine and unverified learned content are excluded. Native width drift fails closed rather than comparing different lengths.

## UI and API integration

The model editor supports a blank/native dimensions field or a bounded explicit integer. Saving configuration refreshes index status and never starts a rebuild. The authenticated GET `/api/embedding-index` exposes selected encoder, stored active generation, current-compatible coverage, retained data and job progress. POST `/api/embedding-index/{action}` supports explicit start/pause/cancel/resume. Every action requires the expected job ID (nullable when none); start additionally requires the expected selected encoder revision. These are checked inside the core SQLite transaction, not merely in the UI. A stale tab cannot silently confirm a different job or encoder.

The panel distinguishes configured selection, active generation and job identity; a stale index is labelled as requiring rebuild. Cost-bearing actions require confirmation. Resuming a paused/failed job with an uncertain prior batch requires an additional explicit checkbox. A lost action response locks further actions until a successful status reconciliation; no POST is automatically retried. A refresh requested during another read is queued so saving configuration cannot leave a silently stale view. Cancellation retains active data and warns that an already in-flight request may have been billed. Empty native-width databases pause without a paid dimension probe; configured-width empty rebuilds can complete without requests.

Contract/API focused tests and independent read-only core/UI review passed on the isolated draft. Actual Vue types, integrated final regression suite/build and browser interactions remain release gates; a mocked API action test verifies forwarding rather than the core atomicity proof.
