# Declared plans and bounded historical reads

This slice adds finite, scene-scoped plans, not a calendar, reminder system, or evidence of real-world completion. All three settings default to off: `memoryCommitmentsEnabled` (learning/storage), `memoryCommitmentsAnswerEnabled` (Planner reads), and `memoryHistoricalReadEnabled` (historical reads). Disabling learning does not erase authorized records; revocation maintenance still runs with feature flags off.

## Current plan semantics

A proposal preserves participants (at most eight), polarity, modality, conditions, temporal scope, and explicit time bounds. Unknown dates remain unknown. Only an explicit self-declaration can confirm for that participant. Everyone must confirm the same terms version. A new unconfirmed proposal does not replace the previous confirmed arrangement. Once a newer arrangement has been activated, loss of its confirmation evidence yields **incomplete**, not a silent return to an earlier confirmed arrangement. Completion is self-reported; loss of completion/cancellation evidence yields **needs review**. The open view includes pending and needs-review plans; completed/cancelled plans have a separate filter.

The existing learning call may carry a structured command. There is no additional per-message model call. The trusted server requires one available, explicit self-declaration source. Its transient text is checked but not copied into persistent memory. A declaration backing stores a typed internal marker and opaque digest, never model-expanded plan text or raw chat. Internal markers are excluded from ordinary search, person profiles, reconciliation targets and embedding indexing. Actual terms live in the typed plan store and retain source authority. This is mechanical admission, **not semantic verification of the model's extraction**.

Amendments retain required proposal groups: alternatives within a group are OR; all groups are required (AND). Copying an old title into new terms cannot shed its source dependency. Privacy removal prunes complete proof groups and removes terms if a required group has no surviving proof. Ordinary version drift never permits rebinding. Privacy-only OR continuation requires the exact pre-operation binding and the exact resulting revision/epoch, with unchanged semantics and an intersection of existing proofs.

## Planner and Replyer

`memory.commitments` reads bounded current states (open by default; terminal/all explicitly selectable). `memory.commitmentHistory` requires a plan reference actually delivered in the same turn. `memory.history` requires an assertion actually delivered by a current memory read. Historical anchors cannot silently upgrade to a newer version.

The Planner selects whole receipts with `stateEvidenceIds`. All conditions, participant coverage, time qualifications, declaration status and required dependency groups stay together under the byte budget. Omission removes dependent conclusions and optional drafts; it does not mean no record exists. Exact delivered state and mutation snapshots remain cancellation/commit guards. Historical-reading turns cannot generate learning proposals. After reading current plan state, free-form derived memory writes and detached new proposals are rejected; structured amendments/confirmations use the typed state path. A fresh independent source-only learning task remains available.

Historical output means **previously recorded**, not current truth. Assertion queries apply the recorded-time cutoff before the SQL result limit. Unknown times, imported legacy revisions, retention gaps and unavailable source metadata are qualified. Plan history returns up to twenty complete retained versions through the exposed anchor. Original source-message bodies are unavailable; this is not a full chat replay or a complete event-sourced reconstruction. Assertion-history statuses are labelled as the saved record state. Plan-history confirmation evidence can be appended or withdrawn within a terms version: its view is the currently retained and authorized declaration state for that version, not an exact historical confirmation snapshot. The recorded timestamp identifies when the terms version was recorded.

## Privacy, recovery, and limits

Scene/person scope, exact revisions/epochs, source revocation and complete proof groups are rechecked. A failed pre-recall inspection still records the independent durable root revocation intent before local rollback, so failure cannot silently discard a withdrawal. Restore replays only causally identified, already-applied derivative events once; a higher local revision alone is not proof of application. Missing newer plan/confirmation material quarantines an older snapshot rather than reconstructing it from a hash. Existing restored-model admission holds and incomplete-accounting coverage remain unchanged.

Reads retain explicit bounds: at most 200 inspected plan heads per scene, at most twelve returned current views, at most 64 terms versions, and bounded inherited evidence. A capped query is reported as limited, not complete. Maintenance is not restricted to the read-page prefix. These limits are not a scalability or quality claim.

Validation uses deterministic scripted models, synthetic adapters, SQLite persistence/restart, API handlers and actual Planner/Replyer handoff. It does not establish real-model intent extraction accuracy, social agreement, reduced paid-token consumption, or production performance. Multi-topic experiences, generic salience/hot-cold consolidation, and the remaining modularity/performance work are separate subsequent slices.
