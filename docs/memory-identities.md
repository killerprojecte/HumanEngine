# Verified identity links and scoped aliases

Identity administration is a separate, bounded registry. Administrators explicitly link stable `(adapterId, accountId, personId)` endpoints; matching nicknames never link people. Unlink removes one edge; split removes every edge crossing the selected partition, including alternate paths in a cycle. Original messages, sources, memory scopes and people are not rewritten.

`memory.identities` returns one qualified whole-page receipt. It lists only members in the current adapter/account that already have currently authorized, non-internal person records in the exact scene. A global administrative link does **not** authorize another scene, private conversation, account, or hidden person. `memory.person` remains exact-person. Alias labels are exact-scene, explicitly sourced and time-qualified; manual aliases are administrative declarations, not inferred personal facts. The server-only observation port requires a current exact source/sender snapshot; the model and management API cannot fabricate an observation source.

Prepared, copied, partial or byte-budget-omitted pages confer no identity authority. Actual delivery binds the registry revision and full current alias projection. Unlink/relink ABA, alias expiry, source edits/recalls and model-read policy revocation invalidate stale use. Identity-derived interpretation cannot be saved via contextual `learning.propose`, `habits.propose` or `experience.propose`: this slice does not introduce a cross-person assertion dependency graph. Fresh independent source-only learning remains available. Links are never a workaround for the existing parent-scope gate.

## Management and recovery

Authenticated `/api/memory-identities` uses explicit confirmation, operation IDs and revision CAS. No optimistic UI success; a conflict requires refresh. Administrative views may inspect the global registry; model views cannot. Manual alias creation requires a real scene with the endpoint's adapter/account. The fixed actor identifies the authenticated administrative surface, not a multi-user account audit system.

Every mutation journals a body-free typed intent before its local effect. Current trusted snapshots can witness the exact registry state; revocation suffixes replay with exact before/after hashes. Missing post-backup grant or alias material requires a newer trusted backup rather than reconstructing a label from a hash. A root source-recall intent with interrupted alias cleanup quarantines restoration. Normal recall clears corresponding observed alias bodies in the same local transaction even when learning/read controls are off. Edits make old observations inapplicable without pretending that source-body history exists.

Bounds are explicit: 32 endpoints per component and 4,096 edges and aliases. The 16,384-operation envelope reserves one future revocation slot for each stored edge/alias: operations + edges + aliases must stay within 16,384. New grants and no-ops cannot consume those slots, so existing live resources can still be removed when new grants are at capacity. There is no silent eviction of CAS history; an empty exhausted registry rejects new grants until an explicit future maintenance scheme is implemented. A model page has at most 32 currently authorized members and 64 aliases, otherwise it rejects as limited instead of presenting an incomplete identity conclusion. These are bounded administrative links, not automatic real-world identity verification, general identity inference, merged cross-scene dossiers, or a new permission system.
