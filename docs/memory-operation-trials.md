# Explicit operation trials and user-reported support

Slice 18 connected implementation. This is not a learned permission system, an objective reward model, a scientific benefit test, or a general policy programming interface.

## Consent and authority

The default-OFF `memoryExperienceFeedbackEnabled` flag enables a narrow continuation of the existing three-action experience experiment. Existing administrator-active policies and explicit style preferences retain their old authority. A new operation instruction can create a seven-day trial only while experience intake, hints, scene learning and the new flag permit it. Changing the new flag advances an independent persistent revision; OFF→ON does not reactivate an old trial or reprocess old messages.

The policy remains `validated`; a separate exact-version trial receipt authorizes consumption of its fixed hint. The receipt phase is `trial` or `promoted`, with independent mutation version, instruction, validation receipt, requester, original policy-evidence version and expiry. Promoted means **two independent user reports said the observed operation helped**, not that response quality, task success or causal benefit was established. The two-root rule is a deduplication gate, not statistical validation. Neither phase expands scene/person access, actions, send rights or model budget.

Trial eligibility currently requires scene learning to remain enabled. Turning learning OFF pauses trial/promoted hints and irreversibly invalidates already captured trial turns, including requests waiting for a physical model slot and late ACK-to-use mapping. A fresh turn after learning is re-enabled may use the same still-current trial; paused feedback is not replayed. In contrast, unrelated administrator-active or prior explicit-style policies keep their existing rules. Independent memory-read/personalization pause, source availability, policy version, expiry and current recovery authority remain gates. Administrative inspection does not grant model-read permission.

## Real operation and feedback path

The three actions stay fixed: `exact_person_before_semantic`, `verify_plan_qualifiers`, and `conclusion_before_detail`. Only the first two have observable operation receipts suitable for this feedback path. A selected style hint is not marked applied from a transport ACK and cannot obtain user-reported-operation promotion.

A live nonbot message must reply to an actual same-scene bot target. Explicit person/plan instructions undergo the current mechanical validation before a trial starts. Runtime consumes matching fixed hints. The person operation is a nonempty, authorized exact-person lookup before any semantic search, including an empty semantic search. The plan operation is a complete delivered relation-evidence packet, not merely any returned memory. Neither establishes that the model understood the evidence or wrote correct prose.

The current Runtime does not support editing bot ACK messages. User feedback sources retain their first source-event reference when enrolled; bot targets are the acknowledged canonical message ID in the current authorized preview. This does not claim first-send revision binding for an unsupported versioned-bot-message protocol.

The exact positive phrases are “这次先查我的记忆有帮助” and “这次先核对计划条件有帮助”. They must match the actual applied operation linked to the real acknowledged bot target, current policy version and original requester. Generic thanks, silence, quotes, style exposure, ambiguous targets, another person/action, repeated roots, edits of a consumed root and model-proposed scores cannot promote. The first accepted report changes only the receipt; the second distinct source-root, target-root and turn causes a separate policy/receipt CAS transition. Old evidence is not rebound to an unrelated newer semantic policy.

Explicit operation cancellation accepts “取消先查我的记忆” / “不要再先查我的记忆” and “取消先核对计划条件” / “不要再先核对计划条件”. Cancellation needs the exact selected policy and requester but does not require the operation to have happened. Action-specific negative feedback still requires actual application. Old style cancellation remains style-specific.

## Mechanical validation is not effectiveness

Version 2 validates the same closed action/condition/template contracts and independent fixed synthetic behavioral contexts through the **same operation-eligibility function actually used by Runtime**. It covers empty and wrong-person reads, search-before-person, invalidated contexts, incomplete/mixed plan packets, style and ACK non-application. Dataset/rule hashes and disjoint fixed roots are bound in the `mechanical_only` receipt. This runner calls no model, does not grade generated language and cannot certify real-world benefit.

## Revocation, privacy and recovery

Source recall/delete removes affected feedback and trial dependencies under the existing root-intent-first transaction. Source edits invalidate exact current evidence without inventing a new independent vote. Negative feedback, explicit withdrawal, policy changes, expiry and flag revisions prevent stale in-flight use. Retained observations are not silently promoted after restart.

Trial authorization mutations use the independent recovery authority journal before local changes. Restoring an old snapshot without the newer instruction, positive report, validation or applied-use materials quarantines the result rather than recreating support. Restrictive transitions can be replayed only against the matching receipt. This is the existing trusted-snapshot/latest-authority contract, not physical deletion of uncontrolled third-party backups. Model accounting HOLD and real billing clocks remain independent of synthetic event times.
