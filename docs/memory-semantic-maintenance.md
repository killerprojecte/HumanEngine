# Incremental attributed semantic views

> Slice 17 implementation and aggregate verification completed on 2026-10-29: 1,507/1,507 offline tests, generated-contract checks, runtime/Nuxt types, production build and final formatting passed. An independent boundary review ran 82 focused cases separately; that is not an additional aggregate total. See the unified implementation status for the preservation and publication boundary.

This optional layer proposes summaries, possible duplicates and exact-anchor declaration groups. It does not replace ordinary assertions, merge identities or records, prove a claim true, or establish that a shared real-world event occurred.

## Controls and scheduling

`memorySemanticEnabled`, `memorySemanticAutoAdmissionEnabled` and `memorySemanticAnswerEnabled` default to OFF. The first permits new committed original declarations to notify a bounded background coordinator. The second permits structurally eligible attributed summaries to be admitted automatically; it is not a semantic-quality certificate. Active explicit/observed parents are a structural eligibility check; disputed parents do not qualify for auto-admission. Undetected semantic contradictions are not certified absent. The third permits qualified views to be read through `memory.summaries`. Scene learning and independent memory-read/personalization policy still apply. Admin inspection does not imply model-read permission.

Notifications are ephemeral, post-transaction and exact-version bound. A rollback, revoked source, changed subject partition or OFF→ON policy change cannot reuse an old snapshot. Restart does not scan or replay old chats or run historical model jobs. Processing waits for foreground work and uses the existing managed Router, maintenance admission, real billing clock and recovery accounting HOLD. The entire canonical messages-plus-tool-definitions input has a 65,536 UTF-8-byte limit; oversize inputs are rejected whole, never shortened by dropping conditions. This is not a token count or a provider-framing cap. It makes one bounded semantic completion per captured input; provider retries remain subject to the same physical-request guards and accounting. Started input receipts survive restart and do not become runnable jobs or free retry allowance. These receipts do not replace the cost ledger.

## Evidence, usefulness and truth

A subject partition contains 2–12 complete, currently authorized original learned assertions. A larger or incomplete partition is limited rather than silently truncated. This is a model-input bound, not a claim of at most 12 SQL reads: current resolution authorizes the scene and then selects a subject partition. The retained candidate cap is likewise a storage bound, not a constant-time query guarantee. New or changed relevant declarations make a previously captured partition inapplicable. Every declaration actually shown to the proposer remains a required dependency, even when the model selects fewer IDs as its topical focus. Required parents are AND; the original alternative proofs inside each parent remain OR.

Original scene/message roots are deduplicated across event edits. Multiple assertions from one source are not independent votes. Root counts do not increase truth confidence. Derived semantic text is never fed back as an original assertion or recursively summarized. Possible-duplicate views do not delete or combine records. All source stance, negation, conditions and time qualifications remain attached to the original declarations.

An exact shared event identity may support a bounded group of separately attributed declarations. Equal titles, nearby timestamps and identity links are not shared-event evidence. A grouped declaration view must not infer participation, outcome, causality or emotion. The grouping includes the complete bounded structural association qualifications: candidate/admission status, negation, possibility, temporal scope, conditions and unknown times. These qualifiers are included in both the proposer input and final whole-page handoff, not silently replaced by the event ID.

Weak hypotheses have a fixed seven-day applicability window. Expiry is `review_needed`, not a determination that the historical statement was false; it does not automatically cause a new model run.

## Read and lifecycle boundaries

Model handoff is a whole qualified page, including every original declaration and its limitations. Budget omission cannot retain an unsupported generated summary. A summary read does not authorize new free-form, habit or strategy learning from its prose; a fresh independent source-only turn remains eligible under normal learning rules.

Source withdrawal and terminal deletion prune the affected proof alternatives and reverse dependencies, including indirect parent dependencies. Independent surviving proofs may be requalified only through the trusted privacy lifecycle's captured old→new reference map. Ordinary edits or metadata/version drift invalidate current applicability without pretending to be privacy deletion. Unknown traversal or unsupported recovery state fails closed, not as a false proof that permits destructive cleanup.

Administrator review uses exact candidate-version CAS. It cannot bypass missing source qualification, restore stale original bodies or confer truth. Stale admin rows expose only minimal management metadata. The layer retains current candidate state and minimum deletion markers; it is not a complete semantic-candidate revision archive.

## Recovery and limits

Semantic mutations participate in the independent authority journal before local mutation. Review changes replay only against exact material and hashes. Missing new candidate/attempt material requires a newer trusted backup rather than fabricated text or a reset attempt. Recovering a database does not automatically run the semantic model.

Current bounded capacities are 40 retained candidates per scene and 4,096 per instance, including deletion markers; attempts are separately bounded. Capacity failures are explicit. No destructive consolidation, unrestricted topic discovery, summary-of-summary hierarchy or demonstrated real-model quality benefit is claimed. Real API evaluation remains separately authorized.

## Administration and observed UI checks

The authenticated semantic panel lists current qualified candidates, including fresh
rejected candidates for deliberate review. Admission/rejection uses exact version CAS
and explicit confirmation; a conflict does not display optimistic success. Public model
reads hide rejected entries. Stale management rows contain only ID, version, saved status
and an unavailable reason, never stale candidate text or sources. A review cannot refresh
missing parents or silently extend a hypothesis deadline. Scene switches, session loss
and newer requests clear or cancel older displays.

The synthetic production page was observed displaying three qualified candidates and
retaining negative, possible, past and conditional qualifications. An explicit rejection
advanced the displayed candidate from version 1 to version 2. All three controls were visible. Turning automatic admission OFF persisted after save and
reload while maintenance and answer use remained ON. Turning maintenance and answer use OFF
then produced the explicit disabled panel. Re-enabling maintenance left automatic admission
and answer use OFF independently, retained rejected version 2, and permitted an explicit
administrator re-admission to version 3. Episode qualifications and complete original
declarations remained visible, with no layout issue observed in the captured page.
These are actual UI checks with synthetic records, not real-model evaluations.
