## Intentional safety-first limits after repair

- The concept index covers a finite, documented set of Chinese/English meme concepts; it is not general multilingual semantic search. Original model tags remain unchanged.
- A single extraction may combine multiple source clauses, so its source group is conjunctive: recalling any member invalidates that proof. Separately extracted exact-content proposals are alternative proofs, preserving genuinely independent support. This intentionally may over-withdraw a multi-source summary rather than guess which clause supports which fact. Source-only learning keeps extraction independent from remembered private facts. Different-wording semantic merges may remain separate immutable records: only exact normalized text gains independent proof alternatives. This favors recall correctness over universal semantic deduplication.
- Legacy learned memories cannot have missing dependencies reconstructed reliably. Relevant recall therefore quarantines unknown legacy lineage visibly and reversibly; administrative content review is required to take manual ownership. A metadata edit or lock cannot bypass dependency checks.
- Habit policy is bounded (30-day half-life, 90-day retention, 128 current independent-author votes). Dropped evidence contributes no weight; a watermark prevents replay from restoring old authority. Legacy unknown-scope/unknown-time habits remain reviewable but contribute no active weight until renewed from trusted evidence.
- Queue recovery is bounded and process-local. Overflow, exhaustion and partial application are exposed. Partial application cannot be blindly replayed; process restart deliberately does not replay raw chats.
- Grounding guards target observed chronology, inventory and feedback-promise overclaims. Passing examples does not prove factual accuracy for all possible natural-language outputs.

`lineageStatus: verified` denotes a trusted extraction boundary and structurally valid support graph. It does not prove semantic entailment, truthful content or model understanding.

The follow-up guard applies to **source-only extraction**, including candidates that omit `personId`. It recognizes a finite set of singular Chinese/English pronouns, ignores quoted third-party language and common non-personal words, and accepts only a supported affirmative self-declaration from the cited fact subject or an unchanged complete cited source statement. A declared person scope also constrains that literal shortcut to the same author. Hypothetical/negative/joking declarations do not license factual pronouns. The first guard revision never rewrote a referent or made another model call. A later authorized live run proved that rejection alone lost a useful nickname correction. The current repair draft therefore adds at most one bounded neutral re-extraction pass before any candidate writes, using the same original source context and revalidating source, subject, kind and scope; it does not silently replace pronouns or claim a repaired candidate is automatically true. Useful valid siblings remain isolated from rejected candidates. Corrected live learning acceptance is still pending.

This is not universal semantic entailment, pronoun resolution or factual truth verification. Contextual proposals with trusted parent dependencies are a separate path; the new extraction guard does not claim to validate every assertion in contextual or manual knowledge. Neutral facts learning successfully under the revised prompt still needs the specifically authorized live retest.
